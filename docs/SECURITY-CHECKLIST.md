# 배포 전 보안 체크리스트

체크리스트는 구현을 대신하지 않습니다. 서비스의 데이터 등급, 위협 모델, 법적 의무에 맞춰 항목과 증거를 배포 기록에 남겨야 합니다.

## 비밀과 공급망

- [ ] `.env`, DB 비밀번호, 관리자 초기 비밀번호가 Git 이력·Docker 빌드 컨텍스트·CI 로그에 없는지 확인했습니다.
- [ ] 운영 비밀은 Secret Manager/Vault/KMS 계열 시스템에서 짧은 수명 또는 회전 가능한 형태로 주입합니다.
- [ ] 초기 관리자 생성을 껐고, 기본 계정의 비밀번호를 회전했습니다.
- [ ] Maven 의존성과 베이스 이미지의 취약점을 스캔하고 예외의 소유자·만료일을 기록했습니다.
- [ ] SBOM, 빌드 출처, 이미지 다이제스트를 보관하고 서명된 이미지만 배포합니다.

## 네트워크와 HTTP

- [ ] 인터넷에서 DB와 Actuator 관리 경로로 직접 접근할 수 없습니다.
- [ ] TLS 1.2 이상, 유효한 인증서, HTTP→HTTPS 리다이렉트를 실제 공개 주소에서 확인했습니다.
- [ ] 신뢰 프록시만 전달 헤더를 쓰며 외부에서 들어온 같은 헤더를 제거합니다.
- [ ] HTTPS 응답에 HSTS가 있고 조직이 준비되지 않았다면 preload는 꺼 두었습니다.
- [ ] CSP를 실제 화면의 필요한 출처만 허용하도록 조정했고 `unsafe-inline`/`unsafe-eval`을 추가하지 않았습니다.
- [ ] 업무 iframe은 동일 출처만 허용하며 `frame-ancestors 'self'`와 `X-Frame-Options: SAMEORIGIN`을 실제 응답에서 확인했습니다.
- [ ] 세션 쿠키에 `Secure`, `HttpOnly`, 적절한 `SameSite`, 제한된 Domain/Path가 적용됩니다.

## 인증과 계정 수명주기

- [ ] 비밀번호 비용을 대표 운영 장비에서 부하 시험했고 과도한 메모리 고갈이나 짧은 지연을 피했습니다.
- [ ] 로그인 실패 메시지와 응답 시간으로 사용자 존재 여부가 쉽게 구분되지 않습니다.
- [ ] NAT·프록시 환경에서 IP 제한 오탐과 우회 가능성을 측정했습니다.
- [ ] 공개 회원가입이라면 이메일 소유 확인, 봇 방지, 약관 동의 이력을 구현했습니다.
- [ ] 비밀번호 재설정 토큰은 충분히 무작위이고 짧게 만료되며 1회 사용 후 폐기됩니다.
- [ ] 관리자와 민감 작업에는 MFA/패스키 또는 조직 SSO를 적용했습니다.
- [ ] 퇴사·휴면·삭제·잠금·역할 변경 시 모든 노드의 세션이 폐기됩니다.
- [ ] 마지막 관리자 보호와 긴급 관리자 복구 절차를 시험했습니다.

## 권한과 입력

- [ ] URL 규칙뿐 아니라 서비스 메서드에서 객체·기능 권한을 검사합니다.
- [ ] 관리자 화면의 모든 상태 변경이 POST이며 CSRF 토큰 없이는 403입니다.
- [ ] IDOR/BOLA 관점에서 다른 사용자의 객체 ID를 바꿔 요청하는 테스트를 수행했습니다.
- [ ] 헤더·폼 본문·파라미터 개수·자격 증명 길이 제한을 실제 프록시와 애플리케이션에서 시험했습니다.
- [ ] JSP 출력, 동적 URL, 이메일/CSV/파일 내보내기의 문맥별 인코딩을 검토했습니다.
- [ ] 업로드를 추가했다면 크기·확장자·실제 MIME·파일명·저장 위치·악성코드 검사를 구현했습니다.
- [ ] SSRF가 가능한 외부 URL 입력, 역직렬화, 템플릿 표현식, 명령 실행 경로가 없는지 확인했습니다.
- [ ] DB 메뉴 경로가 외부 URL·쿼리·프래그먼트·경로 이동과 설정된 예약 경로를 거부하는지 시험했습니다.

## 데이터베이스와 로그

- [ ] 런타임 DB 계정에는 필요한 테이블 DML만 있고 DDL·관리 권한이 없습니다.
- [ ] DB 통신은 인증서를 검증하는 TLS이며 백업도 암호화됩니다.
- [ ] Flyway 변경을 운영 복제본과 호환성 기간을 고려해 시험했습니다.
- [ ] SQL 바인드 값, 비밀번호, 토큰, 세션 ID가 애플리케이션·감사·프록시 로그에 없습니다.
- [ ] 세션 관리 HTML과 감사 이벤트에 원 세션 ID가 없고 종료 요청은 CSRF로 보호됩니다.
- [ ] 감사 로그 접근, 위변조 방지, 중앙 전송, 경보, 보존·파기 정책을 적용했습니다.
- [ ] 슬로 쿼리 로그 크기와 개인정보 포함 가능성을 모니터링합니다.

## 가용성과 대응

- [ ] 다중 노드에서 rate limit과 세션 저장소를 공유합니다.
- [ ] DB 풀 총합, 요청·프록시·DB 시간 제한, graceful shutdown을 부하 시험했습니다.
- [ ] liveness는 재시작 필요 상태만, readiness는 트래픽 수신 가능 상태만 반영합니다.
- [ ] 백업 복구 훈련이 RPO/RTO 안에 끝났고 담당자 없이도 문서로 재현할 수 있습니다.
- [ ] 보안 이벤트 경보, 계정 탈취 대응, 비밀 회전, 취약점 긴급 배포 절차를 연습했습니다.
